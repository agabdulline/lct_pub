# Данные

Исходные данные хакатона в git **не хранятся** (≈16.5 ГБ, лимит GitHub 100 МБ на файл, данные выданы только участникам).
Каждый участник кладёт их локально в `data/raw/` — структура ниже.

## data/raw/

| Файл | Содержание |
|---|---|
| `ext-journal-2019.csv` … `ext-journal-2026.csv` | Журнал событий СМВУ по годам, 313.5 млн событий, 2026 — по 30.06. 2019–2024 поставлялись архивами `.7z`, распакованы |
| `справочник_каналов_датчиков.csv` | 11 485 каналов: подсистема, тип датчика, тег, название, объект |
| `справочник_объектов_диспетчер.csv` | 95 объектов: район → объект → подобъект, названия обезличены |
| `журнал_событий_пример.csv` | Пример журнала за 01.08.2026 — другой формат кавычек и булевых |

Около 16.5 ГБ. Объёмы и периоды по годам — `docs/data-format.md` §1.

## Схема журнала

`ид_события, ид_канала_данных, дата, время, тревожное, значение_датчика`

- `тревожное` — `t`/`f` в `ext-journal-*`, `true`/`false` в примере.
- `значение_датчика` — число **или** состояние: `Норма`, `Неисправен`, `Неопределен`, `Обнаружен дым`,
  `Обесточен`, `Затоплен`, `Рычаг сдернут` и др. Состояния — основной источник меток.
- `ид_события` может повторяться в разные моменты: дедупликация по `(канал, ид_события, время, значение)`.
- Время без часового пояса. Принимаем Europe/Moscow (см. `docs/QUESTIONS.md`).
- События пишутся при изменении состояния, а не периодически: отсутствие событий не означает исправность.

## Особенности

- Газовые датчики — 71% строк за 2019–2026 и почти без тревог. Сервис хранит весь журнал без потерь в архиве Parquet,
  а в рабочей базе — значимые изменения и итоги (`docs/architecture/data.md` §2).
- В справочнике каналов у части строк переносы и запятые внутри кавычек — читать только CSV-парсером, не `cut`.
- У 10 638 из 11 485 каналов в `название_датчика` есть пикет (`ПК86-85`, `ВШ ПК88,5`).
- Полный формат, словари значений и дефекты — `docs/data-format.md`; выводы по данным — `docs/research/data-findings.md`.

## Внешние наборы — data/external/ (версия 2, этап 14)

Открытые чужие наборы для направлений, которых нет в данных хакатона. В git не хранятся: скачиваются командой
с проверкой sha256 по реестру `backend/config/external_datasets.yaml`. Как они встраиваются и чем отличаются от
данных хакатона — `docs/architecture/external-data.md`.

```bash
make external D=magdeburg        # = python -m app.cli external download|prepare --dataset magdeburg
```

| Путь | Что |
|---|---|
| `external/<набор>/raw/` | Файлы как скачаны, sha256 совпадает с реестром |
| `external/<набор>/prepared/` | `objects`, `channels`, `events` (журнал в формате эмулятора), `labels` (разметка — эмулятор её не передаёт), `report.json` |

### Magdeburg — пожар и помехи в цехе

[Indoor Fire Dataset with Distributed Multi-Sensor Nodes (Industrial Hall)](https://data.mendeley.com/datasets/yghykzm4km/1),
DOI 10.17632/yghykzm4km.1, лицензия CC BY 4.0. Один CSV, 35.8 МБ, sha256 совпадает с опубликованным Mendeley.

- 248 502 строки: 9 узлов × момент, шаг ровно 10 с, 10.07 09:30 — 13.07 14:43 2023 года по времени источника (+02:00).
  Пропусков и повторов (узел, время) нет.
- 13 показаний на узел: CO₂, CO, H₂, ЛОС (сырой сигнал), частицы PM0.5 / PM1 / PM2.5 / PM4 / PM10, всего частиц,
  типичный размер частиц, температура, влажность. **Единиц в описании набора нет**: у CO₂ (ppm), температуры (°C)
  и влажности (%) они однозначны по диапазону значений, у остальных не указываются.
- 32 опыта: пожары — дерево 7, свечи 4, кабель 3, хлопок 3; помехи — выхлоп 3, дезодорант 3, дым-машина 2, CO 2,
  этанол 2, садовый мусор 1, **сварка 1, абразивная резка 1**. Флаг набора `fire` отделяет пожар от помехи;
  флаг `nuisance` у этанола и CO — 0, помехами их считаем по описанию набора.

Подготовка (`backend/app/external/magdeburg.py`):

| Что | Как |
|---|---|
| Справочник | Корень набора `9010001` → цех `9010002` → узлы `9010106` … `9010115` («Узел 06» … «Узел 15»). На узле канал цели «Узел» (`901000000 + узел·100`) и 13 каналов показаний (`… + 1` … `+ 13`); `tag` — имя сигнала (`CO2_Room`), `tag_group` — узел (`sensornode0006`) |
| Журнал | 3 230 526 событий = строки × 13. Время — московское без пояса (+1 ч к источнику), значения — строкой как в источнике (`821.0`, `-0.0`), `is_alarm = false` |
| Разметка | 33 интервала на цех, `[первая запись, последняя + 10 с)`: `fire` 17, `nuisance` 15, `unknown` 1. Опыт 13 (одна строка за 3 с до опыта 14 того же вида) склеен с 14-м. Опыт 21 — два вида подряд (этанол, затем садовый мусор) — две метки. 639 строк с флагом аномалии без номера опыта (13.07, 15:02–15:15 МСК) — `unknown`: это не фон, оценка модели их исключает |

Подготовка — 1–2 с.

### VAST 2017 — проезды по заповеднику (синтетика)

[VAST Challenge 2017, Mini-Challenge 1](https://www.cs.umd.edu/hcil/varepository/VAST%20Challenge%202017/challenges/Mini-Challenge%201/) —
синтетический бенчмарк IEEE VIS, лицензия не указана. Архив `MC1Data.zip`, 1.3 МБ: CSV датчиков, описание данных,
карта. [Эталон](https://www.cs.umd.edu/hcil/varepository/VAST%20Challenge%202017/challenges/Mini-Challenge%201/solution/VAST%20Challenge%202017%20MC1%20Solution%20Final.pdf) —
грузовик, который ночами проезжает к посту рейнджеров и сбрасывает отходы.

- 171 477 проездов `Timestamp, car-id, car-type, gate-name`, 01.05.2015 — 31.05.2016, без пояса и летнего времени;
  точных повторов нет. 40 датчиков: 5 въездов, 8 общих ворот, 9 закрытых ворот, 8 постов и база рейнджеров,
  9 кемпингов.
- На въезде машина получает билет с RF-меткой и класс: 1 — легковая или мотоцикл, 2–4 — грузовики по числу осей,
  5–6 — автобусы, `2P` — машины рейнджеров. 18 708 билетов, из них 998 — `2P`. Класс у билета не меняется.
- По описанию набора закрытые ворота пропускают только `2P`. Какие посты рейнджеров стоят за воротами, в тексте нет:
  у постов 0 и 2 94% проездов — не рейнджеры, у остальных — 0–4%, и это ровно нарушения из эталона.

Подготовка (`backend/app/external/vast2017.py`):

| Что | Как |
|---|---|
| Справочник | Корень `9020001` → заповедник `9020002` → 6 групп `9020011` … `9020016`: въезды, общие ворота, кемпинги, посты на общих дорогах, закрытые ворота, посты и база за воротами. Канал — `902000000 + группа·100 + номер датчика` (база — 99); `tag` — имя датчика |
| Журнал | 171 477 событий, значение — билет машины (как номер пропуска в СКУД), `is_alarm = false` |
| Пропуска и допуски | `credentials` — 18 708 билетов с классом; `permits` — билеты `2P` → «Закрытые ворота» и «Посты и база за воротами», 1 996 строк. У остальных групп допусков нет — они открыты |
| Разметка | `violation` по событию — проезд не-`2P` через группу с допуском: 230 проездов 23 ночных рейсов грузовика (только вторники и четверги, 02:00–05:00) и 12 проездов 6 мотоциклов у поста 1 в обход ворот 10.07.2015. `suspicious` по поездке — из эталона: 6 грузовиков, ночующих вне кемпингов в названные даты, и 2 машины с превышением скорости |

Подготовка — 0.3 с. Допуск к воротам взят из описания набора, посты за воротами — по данным (A13).

### Azure PdM — износ агрегатов (синтетика)

[Azure AI Predictive Maintenance](https://github.com/microsoft/sqlworkshops/tree/ebdc49e7ef15808b75660921d7cfdc0c661f78e9/SQLServerAndAzureMachineLearning/ML%20Services%20for%20SQL%20Server/data) —
синтетический набор Microsoft, зеркало в репозитории `microsoft/sqlworkshops` под лицензией MIT. Ссылки в реестре
закреплены на коммит `ebdc49e`: исходный blob Microsoft больше не открывается, копия на Kaggle требует входа.

- 5 CSV, 80 МБ: `PdM_machines` — 100 агрегатов, модели 1–4, возраст 0–20 лет; `PdM_telemetry` — по часам,
  01.01.2015 06:00 — 01.01.2016 06:00, 876 100 строк × 4 показания (`volt`, `rotate`, `pressure`, `vibration`),
  пропусков и повторов нет; `PdM_errors` — 3 919 ошибок `error1–5`; `PdM_maint` — 3 286 замен компонентов с
  01.06.2014; `PdM_failures` — 761 отказ компонентов `comp1–4`.
- **743 из 761 отказа совпадают** по времени, агрегату и компоненту с записью ТО — это замена после отказа.
  42 раза у агрегата в один час отказывают два компонента.
- Единиц в описании набора нет; у напряжения — вольты по имени колонки `volt`.

Подготовка (`backend/app/external/azure_pdm.py`):

| Что | Как |
|---|---|
| Справочник | Корень `9040001` → модели `9040011` … `9040014` → агрегаты `9040101` … `9040200` («Агрегат 001» …), в `meta` — номер, модель, возраст. На агрегате канал цели «Агрегат» (`904000000 + агрегат·100`), 4 показания (`+1` … `+4`), «Код ошибки» (`+5`), «Журнал ТО» (`+6`), «Отказы и ремонты» (`+7`) |
| Журнал | 3 512 366 событий: показания строкой как в источнике; ошибки — `is_alarm = true` (сообщает устройство); записи ТО и отказов — история ремонтов, вход по ТЗ; признаки видят их только в окнах `[T−w, T)` |
| Разметка | 761 отказ на агрегат, `[момент, момент + 1 ч)`, компонент — в `meta.subtype` |

Подготовка — 1.2 с.
